- 用户描述的时间点全部按真实时间轴：

  | 真实时间 | 槽 | 存储帧 | 内容 |

## 2. 回忆滤镜在**底图坐标系**里（关键结论）

对同一张原画（plate）做实验：

- 屏幕坐标固定的"逐像素增益"模型 → 残差 **36–44 rms**；
- 把干净锚帧按相似变换搬运过去的"底图坐标"模型 → 残差 **2.3–16 rms**。

结论：`frame = white + A(u) * (P(u) - white)`，`u` 是底图坐标。于是可以**在底图坐标系里
对多帧做时域融合**，把字幕当离群点剔除。

但增益 **A 还随时间缓慢漂移**（在底图 MOSAIC 上乘一个全局系数会从 0.90 变到 1.09），
且漂移的空间部分不是纯全局标量——所以在渲染时再叠一层**平滑的屏幕空间增益场 R(x,y)**
去吸收它（实测 R 在 σ=8 px 平滑下能把残差压到 2–3 rms）。

## 3. 处理链

```
ffmpeg -v error -y -i ..\ef_iw_letter00.ogv -fps_mode passthrough -pix_fmt yuv444p -f rawvideo all.yuv
python geo_full.py        # 每一帧对 4 张 raw_color 底图做 SIFT + estimateAffinePartial2D
python -c "import mosaic_build as mb,pickle;pickle.dump(mb.build_traj(),open('traj_smooth.pkl','wb'))"
python sky_fit.py         # 天空段：逐帧竖直偏移
python sky_params.py      # 天空段：逐帧 (偏移, 淡入淡出系数) 联合拟合
python mosaic5.py         # 4 张底图各自重建"加了滤镜的底图"（时域中值，抗字幕）
python render_full.py render    # 生成 out_full.yuv（3778 槽）
pwsh -File encode.ps1     # 出 ogv + mkv 并自检
python verify_out.py      # 逐帧核对：改动只允许落在字幕带内
```

### 3.1 几何（`geo_full.py` + `mosaic_build.build_traj`）

- 每帧对每张底图做 SIFT 匹配 + RANSAC 相似变换（scale/rot/tx/ty），存 `geo_full.npz`。
- 单帧 SIFT 有 ~0.1 px 噪声，用 41 帧局部三次多项式平滑；**必须先用局部中值剔除退化拟合**
  （0801 在 n=884 有一个 scale=0.0000 的垃圾解，未剔除时会把段首 40 帧拖偏 4.7% 缩放、
  41 px 平移——这曾导致 n≈900 有 17 万像素被误判成字幕）。
- 平滑函数**不能就地写回**（窗口内读到已平滑的值），否则段首会额外偏移。

四张底图的位姿轨迹（存储帧 → 真实秒）：

| 底图 | 活跃区间 | scale | rot | 平移 | 交叉溶解 |
|---|---|---|---|---|---|
| 0801 | 874–1420 / 33.0–51.3 s | 1.58→1.32 | +1.7°→−1.7° | (−277,−152)→(−120,−41) | 1385–1465 |
| 0301 | 1420–1985 / 51.3–70.1 s | 1.07→1.28 | +0.4°→+4.7° | (−46,−27)→(−194,−139) | 1955–2025 |
| 0401 | 1985–2560 / 70.1–89.3 s | 1.300（恒定） | 0.00°（恒定） | (−44,−22)→(−276,−94) 纯平移 | 2515–2615 |
| 0701 | 2560–3317 / 89.3–114.5 s | 1.49→1.34 | −4.9°→−2.6° | (−187,−24)→(−179,−44) | — |

交叉溶解权重 α 在各自窗口内用最小二乘逐帧求解（`render_full.compute_xalpha`），
单调下降、无跳变。

### 3.2 天空段（`sky_fit.py` / `sky_params.py`）

`_work\sky_mosaic_full.png`（1280×1162，与上一版同一张）代表整段可见的天空。
逐帧在 **屏蔽字幕带（y 280–520）** 后联合拟合 `(dy, γ)`：`frame = white + γ·(mosaic[y+dy] − white)`。
残差 **均值 1.17 rms、最大 2.24**。γ 在 4.93–30.6 s 间为 0.993，淡入（65–107）与淡出
（809–836）逐帧解出。淡入早期 dy 可达 ~459（超出 mosaic 底部 17 px），但**字幕带对应
的行始终在 mosaic 内**，所以不影响修复。

### 3.3 插画段底图重建（`mosaic5.py` + `mosaic6.py`）——本次的关键

回忆滤镜是**深色字形 + 亮色描边**：字幕压到深色画面上时，字形周围会出现一圈**比背景更亮**
的晕。所以单纯"只剔除更暗的离群点"会在底图里留下亮色鬼影。

**第一轮（mosaic5，已作废）**：半分辨率 64 桶时域直方图取中值 + 3 轮全分辨率加权累加。
仍然脏，原因是：**字幕在屏幕上几乎不动，而对 0801/0701 这两段，屏幕上那个位置对应的
底图坐标也几乎不动**（0801 从 n=900 到 n=1400，屏幕中心映射到底图只走了 (589,306)→(567,320)，
约 25 px，比字高还小）。于是底图里那些像素被字幕覆盖的帧数超过一半，**中值也会取到字幕**。

**第二轮（mosaic6，现用）**：用**每张底图自己的那张"绝对干净锚帧"**（`refrences\00NNNN.png`，
已验证与视频帧逐像素相同）来定位字幕：

```
对底图 k 的每一帧 n：
    A_n = warp(锚帧_k, M_n ∘ M_anchor^{-1})      # 该帧的真值背景（无字幕）
    mask_n = |F_n − A_n|max > 22   （锚帧覆盖处，可靠）
    mask_n |= |F_n − bg_模型|max > 26（锚帧没覆盖到的边缘，退回模型）
    mask_n 膨胀 3 px
    把 F_n（按全局系数归一化）加权累加进底图，权重 = 1 − mask_n
迭代 3 轮；同时输出每像素的累加权重 mosweight_*.npy
```

权重图 `mosweight_*.npy` 留作诊断（渲染时不再需要，见 3.4）。

### 3.4 替换范围与"整框无条件渲染"（2026-10 第四轮）

**第三轮**曾把替换范围收成 `y∈[325,400)`、`x∈[80,1200)`，并且只在
`|bg − F| > thr` 的地方替换（自适应阈值 20–32）。用户复审后指出：
**字幕淡入/淡出的那些帧仍有残留或半处理**——因为淡出时字幕对比度掉到阈值以下，
掩码就不再触发。

**第四轮改为：框内无条件整块重渲染**，不再判断"这一帧有没有字幕"，也**不再区分区段**。
框按 `band_bbox.py` 重新实测（1050 帧的逐帧字幕包围盒）：

| 区段 | 行框 | 列框 |
|---|---|---|
| 插画段 | **318–404** | 92–1208 |
| 天空段 | **318–404** | 92–1208 |
| 白场段（含片头/片尾静态字幕） | **272–406** | 92–1208 |

实测字幕本体占 **行 294–400 / 列 103–1197**（插画/天空段集中在行 333–388，片尾那行在行 291–328），
上下各留 ~15 px、左右各留 ~11 px 余量。

片尾白场（存储帧 3318–3441）的实际内容，实测如下——**注意没有 `音楽 麻枝准` 这行字**
（我在第五、六轮说明里凭记忆写错过，已勘误）：

| 存储帧 | 内容 | 墨迹范围 |
|---|---|---|
| 3318–3355 | 字幕 `最後に。` | 行 339–374 / 列 581–699 |
| 3360–3374 | 上一行淡出、下一行淡入 | — |
| 3375–3441 | 字幕 `たくさんの幸せも ありがとう。` | 行 294–325 / 列 461–818 |
| ~3395–3441 | 署名 `音無 雅美`（淡入，约 t≈120.5 s 起） | 行 ~330–378 / 列 ~830–934 |

三者都在白场框内，所以现在**都被抹成纯白**（用户当时的要求是"纯白背景直接覆盖"）。

**边缘羽化**：框的四边做 4 px 线性过渡（`FEATHER = 4`），避免整框替换在边界留下可见接缝；
因为余量 ≥11 px，羽化不可能碰到字幕。

**框外一律逐字节使用原视频**（α=0 时 `rint(1.0·y + 0.0·bgY) == y`，实测框外改动 0 像素）。

底图权重不是问题：实测框内每帧的权重 1 分位 ≥66、均值 ~400，所以整框替换不会碰到
底图样本不足的区域。

#### 3.4.1 两个溶解窗口的例外（2026-10 第五、六轮）

整框替换有个副作用：**溶解段**（两张底图交叉淡入淡出）里，底图模型本身带着几 rms 的偏差，
而框外保留的是原片——两相对照，框会显出一个淡淡的矩形。

处理办法：**只在这两个溶解窗口内**，用**精确干净锚帧**（见 3.3）判断"哪些像素是字幕"，
只重画这些像素，其余像素逐字节保留原片。误判成字幕是无害的（那里 bg ≈ F），
漏判才有害，所以阈值取得很低（`FIX_SUB_THR = 12`，膨胀 5 px，再 1.5 px 羽化）。

同时用 `xfade_fit2.py` 重测了溶解区间与权重：这个窗口原来开窄了（第 1→2 段实际从
存储帧 1374 就开始，旧窗口是 1385；第 2→3 段实际从 1943 开始，旧窗口是 1955），
而且拟合时两张底图共用了一个缩放系数——改用**各自独立的缩放**（`F - white ≈ a·den_A + b·den_B`，
`α = a/(a+b)`）后权重几乎不变，但区间修正了。窗口现在是
**a: 1374–1462、b: 1943–2026**；第 3 个溶解（0401→0701）用户未提出，保持原样未动。
注意 `xalpha2.pkl` 是每 2 帧采样的，**必须插值到每一帧**——否则奇数帧会退回"纯底图 A"，
产生逐帧闪烁。

**⚠️ 真正的根因：轨迹在窗口内是"冻结"的（第六轮才找到）。**

`render_full.M_of()` 把 n 夹在 `traj[pname]` 的范围内。而 `mosaic_build.TRAJ_RANGE`
原来就等于该底图自己的 `PERIOD`，于是**正在淡入的那张底图在溶解前半段完全不动**，
要等到溶解结束、它成为主画面（SIFT 能拟合了）才开始移动。用户一眼看出来了：
"你画上去的遮罩并没有从一开始就随着原本的背景移动"。

修法：把 `TRAJ_RANGE` 放大到覆盖整个溶解窗口，超出拟合范围的部分由 `build_traj()`
里已有的**局部二次外推**填充：

| 底图 | 拟合范围（PERIOD） | 轨迹范围（TRAJ_RANGE） |
|---|---|---|
| 0801 | 874–1428 | 874–**1462** |
| 0301 | 1425–1992 | **1374**–**2026** |
| 0401 | 1990–2572 | **1943**–2572 |
| 0701 | 2556–3320 | 2556–3320（未动） |

已验证：原有范围内的轨迹**逐位不变**（max Δ = 0），所以只有溶解窗口受影响。
外推精度用 SIFT 在 1975/1980/1985 的可用拟合交叉验证过，误差 ≤0.3 px / 0.002 scale。
改完后框内残差：n=1965 由 16.03 → 13.32、n=1980 由 16.91 → 13.60。

**第 1 个溶解的字幕更短**：实测该窗口的字幕只占 **列 360–916 / 行 335–382**，
而通用框是列 92–1208。用通用框会连带重画左侧大片画面（用户看到的"辉光"）。
于是给窗口 a 单独一个窄框 `WIN_A_BOX = (322, 398, 342, 938)`，
重画像素从 27k–38k 降到 18k–22k。

### 3.5 渲染（`render_full.py`）

对每个存储帧：

1. `bg0 = white + Σ_k α_k·(mosaic_k 经 M_k 变换到屏幕 − white)`
   （天空段换成 `white + γ·(mosaic 裁剪 − white)`；白场直接用 white）。
2. **平滑屏幕增益场 R(x,y)**（`Rfit.estimate_R`）：逐通道 `R = (F−white)/(bg0−white)`，
   在 |bg0−white|>30 的像素上做多尺度归一化盒滤波（半径 8/24/72/200），
   三轮只用**向上/向下残差在 (+0.08, −0.12) 内**的像素加权重算。
   `bg = white + R·(bg0 − white)`。
3. 框内**无条件整块替换**（见 3.4）：`out = (1−α)·F + α·bg`，α 在框内为 1、
   四边 4 px 线性羽化、框外为 0。
4. 框外**逐字节保留原始 YUV**（实测 0 像素改动）。
5. 按 `cfr_map.npy` 复制帧写出 3778 槽。

   根因：只在 `|bg−F| > thr` 处替换，而字幕淡出时对比度掉到阈值以下。

### 第五、六轮（两个溶解窗口）

用户第一轮反馈后我改成了"窗口内只重画字幕像素 + 重测区间与权重"，但**没有改善**。
用户的第二轮反馈给出了真正的根因：

1. **第 2 个溶解"新画面没对齐"** —— 根因是 `M_of()` 把帧号夹在轨迹范围内，
   正在淡入的底图在溶解前半段**轨迹被冻结**，一动不动。修法见 3.4.1（扩大 `TRAJ_RANGE`）。
   这是根因，不是权重问题。
2. **第 1 个溶解"左侧辉光"** —— 该段字幕短得多（列 360–916），用通用宽框会连带重画左侧画面。
   修法：窗口 a 单独用窄框 `WIN_A_BOX`。

### 编码产物自检（新增）

第一次重编码出的 ogv 有 **2 个损坏帧**（packet 19/20 底部一条绿色横带，
对渲染结果只有 16–19 dB）。重新编码后正常。因此把 `encode_check.py` 加进流程：
编码后逐 packet 解码、按行统计色度，若相邻行色度跳变 >25 就判为损坏并拒绝安装；
安装后再用 `verify_ogv.py` 复核。当前产物：**0 个损坏帧、PSNR 平均 53.28 dB、最低 40.12 dB**。

期间还修掉一个几何 bug：`geo_full.npz` 里 0801 在 n=884 有一个退化拟合
（`scale=0.0000`），未剔除时会把段首 40 帧带偏 4.7% 缩放 / 41 px 平移，
导致 n≈900 有 17 万像素被误判成字幕。`mosaic_build.robust_keep` 现在会剔除这类点。
